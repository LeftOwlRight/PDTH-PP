# 修复版手动验证

此修复在 `fix/sentry-network-stability` 分支。后台测试不启动游戏；以下实机交互由用户执行。

## 安装范围

测试包只包含 `mods/PDTH++`。安装前备份原目录，然后使用完整的新目录替换；不要混合新旧脚本。
现有游戏安装包含用户自己的 `copactionshoot.lua` 等改动，不能直接把工作副本当作这些改动的合并版。
本轮不自动覆盖这份安装，也不修改 dahm 的个人设置。

需要游戏 Update 23 和 dahm 1.18.1.1。模组发布版本仍为 1.36.0.9；网络协议为独立的 **2**。
协议相同的不同发布版本可以联机。旧版使用发布版本号作为协议的实现需要更新，因为回收消息格式确实不同。

## 测试项目

1. 启动至主菜单，确认 dahm、PDTH++ 和模组设置菜单可用；进入关卡检查炮台、盾窗和交互资源。
2. 单人部署炮台，耗弹、受伤、取消长按回收、成功回收。取消不扣费，成功只扣一次并返还一台设备。
3. 低音量下持续射击，比较正常高帧率与卡顿恢复。恢复时不应快速补发积压子弹；正常射速保持不变。
4. 连续射击中转火，随后以盾牌/弹药包/医疗包遮挡新目标。应停火保持跟踪，并遵守 1.5 秒保留和 5 秒转火冷却；方向未对准或解析不可命中时不浪费弹药。
5. 两人分别测试主机、客机回收。客机完成长按后、等待回复期间切枪或继续射击，不应出现炮台消失却没返还设备。
6. 在有延迟/丢包的连接下重复交互、取消、断线重连。失败退费、成功返还各只发生一次；8 秒未决时出现等待确认/取消提示。完全不响应的主机仍需恢复连接或离开房间才能确定结果。
7. 保持相同游戏和协议，将一端的 **模组发布版本号**改成不同值。大厅可互相发现，实际加入应成功。
8. 分别使用无模组、旧协议、不兼容游戏版本尝试普通大厅、邀请和中途加入。隔离开启的房主应拒绝；新版 PP 客机收到带原因的拒绝回复时应显示对应提示。原版玩家仍只能看到原版拒绝提示。
9. 重开、换关、返回菜单后重新加入；检查 HUD、费用、交互和旧消息没有跨关卡残留。

若有异常，记录主机/客机、复现步骤、是否有长卡顿及当次日志。需要详细射击诊断时，将
`pdthpp_sentry_diagnostics = true` 加入现有 `mods/user.lua` 配置表并重启；平时默认关闭。
